Elasticsearch · Logstash · Beats · Kibana

Four boxes
and a movie

The entire Elastic Stack, learned by building one thing: a Netflix-style search app that is both powered by Elasticsearch and watched by it.

The problem

Why your database gives up on search

-- 6,959 movies. User types "matrix".
SELECT * FROM movies WHERE title LIKE '%matrix%';
  • The leading % kills the index — it's a full table scan, every row, every time
  • Searching overview and cast too? Scan them all as well
  • No ranking. A movie called "The Matrix" ties with one that mentions it once
  • No typo tolerance, no stemming — "matrix" won't find "matrices"

A database answers "which rows match?". Search has to answer "which rows are most relevant?" — a fundamentally different question.

The idea

Turn the book around

A database — read every page

doc 1 → "the matrix reloaded"
doc 2 → "matrix of leadership"
doc 3 → "the notebook"
…6,956 more

An inverted index — check the index

"matrix"   → [1, 2]
"reloaded" → [1]
"notebook" → [3]

Same trick as the index at the back of a textbook. You don't read the book to find "mitochondria" — you look it up and it tells you the pages. That inversion is Elasticsearch's whole superpower.

Component 01

Elasticsearch

A distributed document store built around the inverted index. JSON in, ranked results out, over HTTP.

Document

One movie

A JSON object. No schema migration to add a field.

Index

All the movies

Roughly "a table" — but built for search, not joins.

Shard

A slice of the index

How one index spreads across many machines.

Replica

A copy of a shard

Survives a dead node, and serves reads in parallel.

Scaling is just more shards on more nodes. That's why the same engine runs a movie catalogue and a petabyte of security logs.

Component 02

Logstash

The pipeline that gets data in — and fixes it on the way.

STAGE 1

input

Where it comes from. Files, Beats, Kafka, JDBC, HTTP.

STAGE 2

filter

Parse, convert, enrich, drop. Where the real work happens.

STAGE 3

output

Where it lands. Usually Elasticsearch.

filter {
  # the app renders a user_score facet.
  # not one of our 6,959 movies actually has that field.
  ruby { code => "event.set('user_score', event.get('vote_average').to_f)" }
}

That's the argument for Logstash in four lines: the data you have is never quite the data your app needs.

Component 03

Beats

Small single-purpose shippers that sit on the thing being watched. Deliberately dumb: they tail, remember their place, and forward.

logs

Filebeat

Tails log files and container stdout.

metrics

Metricbeat

CPU, memory, Docker, Nginx, Postgres…

network

Packetbeat

Reads traffic off the wire.

uptime

Heartbeat

Is it up? Is it answering?

Why not have Logstash read the files itself? Because Logstash is a JVM that wants a gigabyte. You can't put that on 500 servers. You can put a Beat on 500 servers.

Component 04

Kibana

The window into everything above.

  • Discover — raw documents, filtered and searched. Where you actually debug
  • Dev Tools — a console straight to the Elasticsearch API. Live all video
  • Dashboards — the charts your manager thinks the whole thing is for
  • Maps, Alerts, ML — the parts we're not covering today

Kibana stores nothing. Every panel is a query against Elasticsearch, run when you look at it.

Putting it together

Two paths, one cluster

──  the catalogue  ───────────────────────────────────────
movies.json  →  LOGSTASH  →  ELASTICSEARCH  →  Elastiflix UI
                 parse, enrich

──  the observability  ───────────────────────────────────
app logs     →  FILEBEAT   →  LOGSTASH  →  ELASTICSEARCH  →  KIBANA
container    →  METRICBEAT ─────────────↗
metrics          (no transform needed — skip the hop)

Note Metricbeat goes straight to Elasticsearch. Logstash is a choice, not a mandatory tax — if there's nothing to transform, don't pay for the hop.

Naming

ELK, Elastic Stack, Elastic Agent

NameWhat it actually means
ELKThe original three: Elasticsearch, Logstash, Kibana. Still what most job descriptions say.
ELK-B / Elastic StackBeats joined in 2015 and broke the acronym. Elastic renamed the whole thing "Elastic Stack".
Elastic AgentOne binary replacing the many Beats, managed centrally through Fleet. Where Elastic is heading.
EFKSame idea, Fluentd instead of Logstash. Common in Kubernetes.

They're the same family. Learn the four boxes and every variant reads as a swap of one box.

The build

Elastiflix

Elastic's own movie search demo — forked and extended until all four components are doing real work on it.

PieceJob in this build
ElasticsearchStores and searches 6,959 movies
LogstashLoads the catalogue, then parses the app's logs
FilebeatShips every search a user types
MetricbeatShips container CPU and memory
KibanaOne dashboard over all of it

The symmetry worth holding onto: Elastiflix is the app using Elasticsearch, and the app monitored by Elasticsearch.
